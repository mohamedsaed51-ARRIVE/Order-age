# Order Age — لوحة أوديت الأوردرات المتأخرة

لوحة متابعة لشيت الأوديت اليومي (عمر الحالة وعمر الأوردر للشركة وخدمة العملاء). مبنية بنفس هيكل وهوية لوحات ARRIVE (V2.0): ألوان رسمية كمتغيرات CSS، خطوط Cairo/Inter، أيقونات Font Awesome، رسوم Chart.js، وضع داكن، RTL.

> **لا تُرفع هنا أي بيانات شحنات أو عملاء أو مناديب.** الويب آب يعرض أعدادًا مجمّعة (يوم × فرع) فقط.

## المحتويات
| المسار | الوصف |
|---|---|
| `src/App.jsx`, `src/lib.js`, `src/ChartBox.jsx`, `src/styles.css` | اللوحة (React 18 + Vite + Chart.js) |
| `src/Reports.jsx`, `src/reports/*` | صفحة التقارير (معاينة A4 + طباعة + Word) |
| `apps-script/OrdersAuditSheet.gs` | سكربت الشيت (تحديث يومي، تاب لكل يوم، التبليغات). نسخة من `Code.gs` |
| `apps-script/OrdersAuditWebApp.gs` | ويب آب يقرأ تابات الأيام ويُرجع JSON مجمّعًا |

## أقسام اللوحة
الهيدر (لوحة المتابعة | التقارير) ← شريط الحالة ← شريط التحكم ← الفلاتر (فترة، إقليم، فروع متعددة، بحث) ← **الصورة العامة** (4 كروت: للمتابعة، أوردر الشركة، خدمة العملاء، حالة فقط) ← **التبليغ والتصعيد** (4 كروت: لم يُبلَّغ بعد، نسبة التبليغ، المتكرر، التحصيل المعرّض) ← صحة الفروع (4 مستويات) ← الاتجاهات والتوزيعات ← الأوردرات المتكررة ← مركز التنبيهات ← مركز الإجراءات ← رؤى الإدارة ← وضع المقارنة (يومان) ← سجل الأوديت اليومي.

- الأنواع الثلاثة **لا تتداخل**: الشحنة تُحسب في نوع واحد (أوردر الشركة، ثم خدمة العملاء، ثم حالة فقط)، ومجموعها = «للمتابعة».
- «خدمة العملاء» نافذة بين حد خدمة العملاء وحد الشركة، وتختفي بعد تجاوز حد الشركة.
- نسبة الأوردرات المتأخرة = (أوردر + خدمة عملاء) ÷ شحنات الفرع (الأقل أفضل). نسبة التبليغ = (أوردر/خدمة اتبلّغ) ÷ (أوردر + خدمة).
- «حالة فقط» تُعرض مع عدد ما عمر حالته يساوي حدّه بالضبط (أول يوم تأخر) لأنه الأغلب ويحتاج مراجعة حدود الحالات في SOP.
- مستويات الصحة (ممتاز ≤2%، جيد ≤4%، انتباه ≤6%، حرج أعلى) وحد التبليغ 50%: **حدود للعرض وليست سياسة معتمدة**، وتُغيَّر من «إعدادات».
- مقترحات الإجراءات والرؤى قواعد آلية وليست قرارات معتمدة ولا ذكاءً اصطناعيًا.
- `?demo=1` أو زر «معاينة» يعرض **بيانات تجريبية غير حقيقية** مع شريط تنبيه، وتُعلَّم التقارير الناتجة عنه بأنها تجريبية.

## التقارير
صفحة «التقارير» (`?view=reports`) تبني تقارير A4 بنفس تصميم تقارير المطابقة: هيدر أزرق بالشعار، أقسام مرقّمة (أولًا، ثانيًا…)، كروت مؤشرات، جداول بصف إجمالي وصفوف مظللة، ملاحظات جودة البيانات، وتوصيات مقترحة. تُعرض كمعاينة، وتُطبع/تُحفظ PDF، وتُحمَّل Word (مكتبة `docx` تُحمَّل عند الضغط).

| التقرير | المحتوى |
|---|---|
| التقرير التنفيذي اليومي | يوم أوديت واحد: المؤشرات، الأقاليم، أعلى الفروع، التبليغات، المتكرر، الحالات، المقارنة باليوم السابق، التوصيات |
| تقرير أداء الفروع | فترة: ترتيب الفروع (متوسطات يومية)، مقارنة بالفترة السابقة، التوزيع الأسبوعي، أعلى 10 مرات لفرع في يوم |
| تقرير التبليغات والتصعيد | فترة: التبليغات حسب النوع والفرع والأسبوع، نسبة التبليغ، المتكرر، الفروع الأقل تبليغًا |

الملفات: `src/reports/model.js` (بناء المستند)، `render.js` (HTML)، `docx.js` (Word)، `src/Reports.jsx` (الصفحة). الأعداد مجمّعة (يوم × فرع) بدون أرقام بوالص أو عملاء؛ قوائم الشحنات التفصيلية تبقى في تابات الشيت.

## عقد البيانات (JSON من الويب آب)
```
{ generated, note, rows: [...], statuses: [...], repeated: [...] }
rows      (يوم × فرع): date, branch, region, total, followup, case_late, order_late, cs_late, case_only, case_first,
                       handled, notified, notified_oc, n_cs, n_int, n_ext, high, repeated, max_streak,
                       cod, cod_oc, sum_oage, max_oage
statuses  (آخر 14 يوم): date, branch, status, n        — شحنات متأخرة في الحالة
repeated  (آخر تحديث):  branch, region, count, notified, not_notified, max_streak, t_cs, t_int, t_ext
```

## التركيب
1. في شيت الأوديت: Apps Script ← أضف ملفين: `OrdersAuditSheet.gs` (نفس محتوى `Code.gs` المستخدم في الشيت) و`OrdersAuditWebApp.gs`.
2. `نشر ← نشر كتطبيق ويب` (تنفيذ باسمك، الوصول: أي شخص)، وانسخ رابط `/exec`. بعد أي تعديل: New version.
3. اربط اللوحة: من «إعدادات» داخل اللوحة (يُحفظ في المتصفح)، أو في Vercel أضف `VITE_DATA_URL` برابط `/exec` ثم أعد النشر (Framework: Vite، Output: `dist`).
4. بدون رابط تعرض الصفحة رسالة إعداد فقط.

## التشغيل محليًا
```bash
npm install
cp .env.example .env.local   # ثم عدّل VITE_DATA_URL
npm run dev                  # أو افتح ?demo=1 للمعاينة
```

## الخصوصية
- **الريبو عام (Public): لا تضع رابط الويب آب في الكود.** اضبطه من «إعدادات» داخل اللوحة أو كمتغير بيئة `VITE_DATA_URL` عند البناء/النشر (Vercel Environment Variables). ملف `.env.local` غير مرفوع (في `.gitignore`).
- الويب آب يعرض أعدادًا مجمّعة بدون أرقام بوالص أو عملاء أو مناديب، لكنها بيانات تشغيلية داخلية.
- `VITE_DATA_TOKEN` (مع `DATA_TOKEN` في خصائص السكربت) يمنع الطلبات العشوائية فقط وليس حماية حقيقية لأنه يظهر في كود الصفحة. للحماية الفعلية استخدم نشرًا خاصًا أو Vercel Password Protection.
- التحديث في اللوحة يقرأ تابات الأيام فقط ولا يشغّل التحديث اليومي؛ التحديث اليومي يتم من قائمة الشيت.

## حالة الاختبار
- `npm run build` ينجح، وعُرضت اللوحة والتقارير في الوضع التجريبي (سطح المكتب، الداكن، الموبايل) بدون أخطاء، وتحميل Word يعمل من الصفحة المبنية (حتى كملف HTML واحد).
- منطق تجميع الويب آب (`oaAggregate_`) اختُبر على تاب يوم محاكى من تصدير 4/11/2026، وتطابقت الأعداد مع الحساب المستقل (2,928 للمتابعة، 2,403 حالة، 193 أوردر، 640 خدمة عملاء، 84 أولوية عالية).
- **لم تُجرَّب** اللوحة على ويب آب منشور في Google فعليًا، ولا الأيقونات والخطوط من CDN في بيئة الاختبار.
