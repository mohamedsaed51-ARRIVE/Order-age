# Order Age — لوحة أوديت الأوردرات المتأخرة

لوحة متابعة لشيت الأوديت اليومي (عمر الحالة وعمر الأوردر للشركة وخدمة العملاء). مبنية بنفس هيكل وهوية لوحات ARRIVE (V2.0): ألوان رسمية كمتغيرات CSS، خطوط Cairo/Inter، أيقونات Font Awesome، رسوم Chart.js، وضع داكن، RTL.

> **لا تُرفع هنا أي بيانات شحنات أو عملاء أو مناديب.** الويب آب يعرض أعدادًا مجمّعة (يوم × فرع) فقط.

## المحتويات
| المسار | الوصف |
|---|---|
| `src/App.jsx`, `src/lib.js`, `src/ChartBox.jsx`, `src/styles.css` | اللوحة (React 18 + Vite + Chart.js) |
| `apps-script/OrdersAuditSheet.gs` | سكربت الشيت (تحديث يومي، تاب لكل يوم، التبليغات). نسخة من `Code.gs` |
| `apps-script/OrdersAuditWebApp.gs` | ويب آب يقرأ تابات الأيام ويُرجع JSON مجمّعًا |

## أقسام اللوحة
الهيدر ← شريط الحالة ← شريط التحكم (تحديث، إعادة تصفية، تصدير CSV، طباعة، ملء الشاشة) ← الفلاتر (فترة، إقليم، فروع متعددة، بحث) ← المؤشرات الرئيسية (8) ← صحة الفروع (4 مستويات) ← الاتجاهات والتوزيعات ← التبليغات والأوردرات المتكررة ← مركز التنبيهات ← مركز الإجراءات ← رؤى الإدارة ← وضع المقارنة (يومان) ← سجل الأوديت اليومي بترقيم وتصدير.

- نسبة المتابعة = شحنات للمتابعة ÷ شحنات الفرع (الأقل أفضل). نسبة التغطية = شحنات سُجل لها إجراء ÷ للمتابعة.
- «للمتابعة» = شحنة متأخرة بأي نوع (مرة واحدة)؛ الشحنة قد تظهر في أكثر من نوع (حالة / أوردر الشركة / خدمة عملاء).
- مستويات الصحة (ممتاز ≤5%، جيد ≤10%، انتباه ≤20%، حرج أعلى) وحد التغطية 50%: **حدود للعرض وليست سياسة معتمدة**، وتُغيَّر من «إعدادات».
- مقترحات الإجراءات والرؤى قواعد آلية وليست قرارات معتمدة ولا ذكاءً اصطناعيًا.
- `?demo=1` أو زر «معاينة» يعرض **بيانات تجريبية غير حقيقية** مع شريط تنبيه.

## عقد البيانات (JSON من الويب آب)
```
{ generated, note, rows: [...], statuses: [...], repeated: [...] }
rows      (يوم × فرع): date, branch, region, total, followup, case_late, order_late, cs_late,
                       handled, n_cs, n_int, n_ext, high, repeated, max_streak
statuses  (آخر 14 يوم): date, branch, status, n        — شحنات متأخرة في الحالة
repeated  (آخر تحديث):  branch, region, count, notified, not_notified, max_streak, t_cs, t_int, t_ext
```

## التركيب
1. في شيت الأوديت: Apps Script ← أضف ملفين: `OrdersAuditSheet.gs` (نفس محتوى `Code.gs` المستخدم في الشيت) و`OrdersAuditWebApp.gs`.
2. `نشر ← نشر كتطبيق ويب` (تنفيذ باسمك، الوصول: أي شخص)، وانسخ رابط `/exec`. بعد أي تعديل: New version.
3. اربط اللوحة: من «إعدادات» داخل اللوحة (يُحفظ في المتصفح)، أو في Vercel أضف `VITE_DATA_URL` برابط `/exec` ثم أعد النشر (Framework: Vite، Output: `dist`).
4. بدون رابط تعرض الصفحة رسالة إعداد فقط.

## التشغيل محليًا
```bash
npm install
cp .env.example .env.local   # ثم عدّل VITE_DATA_URL
npm run dev                  # أو افتح ?demo=1 للمعاينة
```

## الخصوصية
- **الريبو عام (Public): لا تضع رابط الويب آب في الكود.** اضبطه من «إعدادات» داخل اللوحة أو كمتغير بيئة `VITE_DATA_URL` عند البناء/النشر (Vercel Environment Variables). ملف `.env.local` غير مرفوع (في `.gitignore`).
- الويب آب يعرض أعدادًا مجمّعة بدون أرقام بوالص أو عملاء أو مناديب، لكنها بيانات تشغيلية داخلية.
- `VITE_DATA_TOKEN` (مع `DATA_TOKEN` في خصائص السكربت) يمنع الطلبات العشوائية فقط وليس حماية حقيقية لأنه يظهر في كود الصفحة. للحماية الفعلية استخدم نشرًا خاصًا أو Vercel Password Protection.
- التحديث في اللوحة يقرأ تابات الأيام فقط ولا يشغّل التحديث اليومي؛ التحديث اليومي يتم من قائمة الشيت.

## حالة الاختبار
- `npm run build` ينجح، وعُرضت اللوحة في الوضع التجريبي (سطح المكتب، الداكن، الموبايل) بدون أخطاء في الصفحة.
- منطق تجميع الويب آب (`oaAggregate_`) اختُبر على تاب يوم محاكى من تصدير 4/11/2026، وتطابقت الأعداد مع الحساب المستقل (2,928 للمتابعة، 2,403 حالة، 193 أوردر، 640 خدمة عملاء، 84 أولوية عالية).
- **لم تُجرَّب** اللوحة على ويب آب منشور في Google فعليًا، ولا الأيقونات والخطوط من CDN في بيئة الاختبار.
